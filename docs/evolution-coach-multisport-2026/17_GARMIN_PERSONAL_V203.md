# ResurGo v2.0.3 — Séance et Garmin Personal API

- Navigation Séance : séance du jour ou séance personnelle (musculation guidée, course extérieure/tapis, vélo extérieur/PM5, elliptique). Le coach en direct reste accessible depuis Aujourd'hui.
- Garmin lecture seule : https://developer.garmin.com/gc-developer-program/personal/personal-faq et https://github.com/garmin/connect-personal-api-python.
- Clé personnelle par profil sportif, isolée par compte NAS authentifié + profil local déjà synchronisé. AES-GCM/HKDF, clé maître optionnelle RS_GARMIN_MASTER_KEY, sinon RS_PAIR_PEPPER avec séparation de domaine. Ne pas changer cette clé sans migration. Les appareils associés au même compte NAS peuvent accéder à tous ses profils ; pas de cloisonnement entre personnes partageant ce compte.
- Aucune clé dans IndexedDB, export, GitHub ou événements. Jeton en mémoire serveur, renouvelé à expiration. Révoquer la clé chez Garmin en cas de perte. Pas de transfert d'activité vers Garmin.
- Import paginé 30/90/365/1825 jours, récupération santé jusqu'à 30 jours (sommeil, VFC, résumé, poids). Synchronisation automatique profil actif au premier plan, 7 jours de recouvrement toutes les heures ; aucun démon NAS autonome dans cette version.
- Rapprochement profil/type/heure ±5 min/durée et recouvrement, candidat unique. En cas d'ambiguïté, ne pas fusionner. Les deux enregistrements sont conservés, l'import Garmin rapproché est masqué des compteurs ; source par métrique et notes locales conservées. Distance PM5 directe non estimée prioritaire, données Garmin préférées pour les moyennes, cardio et GPS ; données manquantes complétées. Aucun jugement absolu sur la précision des capteurs.
- Le plan tient compte des activités uniques ; recommandation prudente de récupération selon sommeil court, VFC défavorable, séance longue récente. Pas de diagnostic médical ni d'intensité inventée.
- Déploiement NAS : depuis le dossier ResurGo Sync existant, bash upgrade-push-qnap.sh --check puis --apply (script existant télécharge app.py et autres sources ; backup SQLite, public/admin, sans Funnel). Pas de changement Docker Compose, de dépendance ou de worker Push requis. Vérifier /health version 0.2.0-garmin, puis configurer clé dans Réglages. Le code frontend peut être publié indépendamment, ancien NAS renvoie 404 aux nouvelles routes.
- Recette physique et API Garmin avec une vraie clé restent nécessaires. Pas de secret dans les tests. Export FIT/TCX reporté.
